## v1.13.0 · 多人房间

**新增**
- 开始游戏改为模式选择：单人游戏 / 多人游戏
- 多人：加入房间（6 位数字房码）/ 创建房间（2~6 人，房码随机）
- 房间界面：房码复制、成员列表、准备、房主开始、再来一局、离开
- 房主开局后其他成员 2 秒内自动进入选角
- 结算界面新增「返回房间看排名」

**后端**：`rooms` / `room_members` + 8 个 `room_*` 函数（容量、房码格式、房主权限全在服务端）

**踩坑**
- `openMenuPanel()` 只隐藏 `screen-menu`，不隐藏上一个面板 → 离开房间后多人菜单盖在屏幕上挡住点击。改为隐藏所有 `.screen`。
- 单人局会把成绩写进之前待过的房间 → 引入 `Room.runCode`（本局属于哪个房间），只有从房间开局的才提交。
- 开始按钮改走模式选择后，66 个历史回归脚本全部失效 → 统一在 `#btn-start` 后补 `#btn-mode-solo`。

## v1.12.0 · 封号 + 开局作弊横幅

**新增**
- 登录用户累计 3 次异常 → 封账号；访客累计 3 次 → 封设备
- 被封玩家开局显示横条「有作弊者，点击加入对局」，点击进入沙盒对局
- 后台异常页区分"账号行 / 访客行"，可分别封账号或封设备

**踩坑（重要）**
- **访客的 `auth.uid()` 是共享字符串 `'anon'` 而非 NULL**。按它统计会让每个新访客继承别人的异常记录并显示被封；按它封号会封掉全体游客。新增 `_uid()` 统一折叠。
- `cheat_flags.owner_id` 原本 `NOT NULL`，访客存 NULL 会报错 → 去掉约束。
- 真实 IP 拿不到（连续 3 次请求 3 个不同腾讯云出口 IP），IP 封禁方案放弃，改设备指纹。

## v1.10.2 · 修复"一波跳好几波"

**根因**：`endWave()` 递增波次但从不重置倒计时，倒计时残留 ≤0，任何回到战斗的非正常路径都会再次触发结算。实测单局触发 184 次。

**修复**
1. `endWave()` 加幂等锁 `G.waveCleared`
2. `endWave()` 内立即把 `waveTime` 顶到下一波时长
3. `startWave()` / `startGame()` 复位 `waveClearHold` 与 `waveCleared`
4. 反作弊回拉不再回退波次（波次与计时器错位会引发二次结算）

**附带**：临时邮箱拦截（本地 60 条兜底 + 云端 130 条，注册/登录/绑定三处生效）

## 约定的"不要动"

| 位置 | 原因 |
|---|---|
| `js/game.js` 的 `waveCleared` 相关逻辑 | 删了会再现"跳波"bug |
| `#test-hook-start` / `#test-hook-end` 注释 | 构建脚本靠它剥离调试接口 |
| `_uid()` 的 `'anon'` 判断 | 删了会误封全体游客 |
| `Room.runCode` 的赋值时机 | 单人局会污染房间成绩 |
| `sdk/workbuddy-cloud-sdk.js` | 平台提供，随平台升级整体替换 |
